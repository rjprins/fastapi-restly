Declare Your Models#

Restly works with SQLAlchemy models on a declarative base of your own. The base is your class, with its own registry and MetaData, as in any SQLAlchemy project. Restly does not own it. It gives you two kinds of help:

  • fr.ModelDefaults adds Restly’s defaults to your base.

  • fr.IDMixin and fr.TimestampsMixin add common columns to a model.

All of it is optional. Restly’s views also work with plain SQLAlchemy models.

Add Restly’s defaults to your base#

Put fr.ModelDefaults in your base class, before DeclarativeBase:

from sqlalchemy import ForeignKey
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column

import fastapi_restly as fr


class Base(fr.ModelDefaults, DeclarativeBase):
    pass


class BlogPost(fr.IDMixin, Base):
    published: Mapped[bool] = mapped_column(default=False)
    title: Mapped[str]


class Comment(fr.TimestampsMixin, fr.IDMixin, Base):
    content: Mapped[str]
    blog_post_id: Mapped[int] = mapped_column(ForeignKey("blog_post.id"))

fr.ModelDefaults already includes SQLAlchemy’s MappedAsDataclass and AsyncAttrs, so leave those out of the base. Every model on Base then gets these defaults:

  • A dataclass constructor. The constructor takes keyword arguments only: BlogPost(title="Hello"). So a field with a default can come before a field without one, as published does above, and type checkers accept that. Use mapped_column(init=False) for a column that the constructor must not take.

  • Equality by identity. Two model objects are equal only when they are the same object, as for any SQLAlchemy model. So a model object can go in a set, and comparing objects never loads a relationship.

  • A table name. The table name is the class name in snake_case: BlogPost gets blog_post. That is why ForeignKey("blog_post.id") works. Set __tablename__ on a model to choose another name.

  • Datetimes with a time zone. Mapped[datetime] maps to DateTime(timezone=True). Store UTC times in it. PostgreSQL returns them with a time zone, but SQLite returns them without one. For a clock time without a time zone, use mapped_column(DateTime()) on that column.

  • Enums as strings. A column typed with an enum.Enum stores the name of the member, such as RED, as a string of up to 64 characters. It is not a database enum type, so a new member needs no database migration.

  • awaitable_attrs. Code outside a view can await a relationship that is not loaded yet, as Relationship Loading and Async shows.

Change a default#

The base is your class, so you change it as SQLAlchemy documents. To give constraints predictable names, which Alembic needs to drop them later, set metadata. To change how a Python type maps to a column type, set type_annotation_map:

from decimal import Decimal

from sqlalchemy import MetaData, Numeric
from sqlalchemy.orm import DeclarativeBase

import fastapi_restly as fr


class Base(fr.ModelDefaults, DeclarativeBase):
    metadata = MetaData(
        naming_convention={
            "ix": "ix_%(column_0_label)s",
            "uq": "uq_%(table_name)s_%(column_0_name)s",
            "ck": "ck_%(table_name)s_%(constraint_name)s",
            "fk": "fk_%(table_name)s_%(column_0_name)s_%(referred_table_name)s",
            "pk": "pk_%(table_name)s",
        }
    )
    type_annotation_map = {Decimal: Numeric(12, 2)}

Your type_annotation_map entries win over Restly’s. Restly’s entries still apply to the types you leave out. So {datetime: DateTime()} stores the datetimes on this base without a time zone, and enums are still strings. The columns of fr.TimestampsMixin keep their time zone, because the mixin sets their type itself.

For one column, pass the type to mapped_column, as in mapped_column(Enum(Color, native_enum=True)). For one table, set __tablename__.

Set dataclass options on each model, not on the base. For example, class Post(fr.IDMixin, Base, eq=True) makes two Post objects equal when their fields are equal. SQLAlchemy takes the options from the first dataclass class in the bases of a model, and that is often a mixin. So options on the base would apply to some models only, and the base raises fr.exc.RestlyConfigurationError.

Add common columns#

fr.IDMixin adds id, an integer primary key. The database chooses its value, so the constructor does not take it.

fr.TimestampsMixin adds created_at and updated_at. Both are UTC datetimes with a time zone. The constructor sets both to the current time, and SQLAlchemy sets updated_at again on every update. A schema can return them with fr.TimestampsSchemaMixin.

For a different primary key, declare id yourself instead of using fr.IDMixin:

from uuid import UUID, uuid4

from sqlalchemy.orm import Mapped, mapped_column


class Product(Base):
    id: Mapped[UUID] = mapped_column(
        primary_key=True, init=False, default_factory=uuid4
    )
    name: Mapped[str]

The two mixins are SQLAlchemy dataclass mixins. On a base without fr.ModelDefaults, SQLAlchemy makes each model that uses them a dataclass. The constructor of that model then takes keyword arguments only, and requires every field without a default.

Use the base in your app#

Everything that asks for your models’ tables takes the base:

  • fr.db.async_create_all(Base) creates the tables during development.

  • fr.testing.configure_tests(base=Base) builds and cleans the test tables, as Test APIs with RestlyTestClient and Fixtures shows.

  • Alembic’s env.py sets target_metadata = Base.metadata, as Deploying shows.

A base only knows the models that have been imported. Project structure shows how one module imports them all.

Models without Restly’s defaults#

Restly’s views and schemas work with any SQLAlchemy declarative model, dataclass or not. Models that you already have can stay on their own base, as Use Restly in an Existing Project shows.

Adding fr.ModelDefaults to a base that already has models changes those models:

  • Their constructors take keyword arguments only, and require every field without a default.

  • Mapped[datetime] columns get a time zone. On PostgreSQL, TIMESTAMP becomes TIMESTAMP WITH TIME ZONE. The migration must say how to read the stored values, as Deploying shows.

  • Enum columns become strings. On PostgreSQL, a native ENUM becomes VARCHAR(64), so that needs a migration too.

Alembic shows these column changes when it generates the migration. Review the migration before you run it.

Put fr.ModelDefaults on the base itself. On a class below another declarative base, it raises fr.exc.RestlyConfigurationError, because Restly’s defaults change the registry of the whole base.
